# EvalForge evidence matrix

This matrix covers the `finance_eval` vertical at commit `4fcec3bc4fa816a533d3445ebc3dc82d38871659` and records what each headline claim rests on. It was produced on 2026-11-10 (Asia/Taipei) on a Linux machine with Python 3.12.15, in a fresh virtual environment, with no API keys set. Only the offline modes and the `mock` provider were run. No paid API was called.

**Update, 2026-11-11 (Asia/Taipei):** three defects in this matrix were fixed in the local working tree on top of that commit (uncommitted, pending maintainer review): the tautological classifier metrics, the unenforced dataset manifest, and the mock run that rewrote a tracked file. The rows below give the result before the fix and the result after rerunning the same commands with the fix. The links to the commit show the code before the fix; the relative links show the fixed files.

Result labels:

- **Verified (local):** I ran the command and the output matched the claim.
- **Verified with defect:** The command ran, and the output shows a known defect.
- **Documented only:** The claim is in the docs, but no command in this review checks it.
- **Not verified:** No evidence was produced.

## Side effects observed

Before the fix, running `python -m finance_eval run --mode live --provider mock` rewrote the tracked file `finance_eval/baselines/live_run_summary.example.json`. In a scratch copy, its sha256 changed from `9c9f751f…0b88` to `e213c95a…65b8`, and `git status` showed the file as modified. After the fix, a mock run without `--live-summary` writes `finance_eval/output/live_run_summary.mock.json`, which `.gitignore` already covers, and the tracked example keeps its hash. A test asserts that `git status` is unchanged after a mock CLI run. Runs against the real `openai` and `anthropic` providers still default to the tracked example path, so their documented behavior is unchanged, and `--live-summary PATH` still overrides either default.

These are still true: `run --mode gold --write-baseline` without `--baseline` overwrites `finance_eval/baselines/baseline_metrics.json`, and `report` rewrites `docs/reports/finance-evaluation-report.md`. To leave the working tree untouched, pass `--baseline` and `--evidence-dir` paths outside the repository, as the case study does.

## Known limitations

Fixed in the local working tree (uncommitted, pending maintainer review):

1. **Tautological classifier metrics** in `finance_eval/metrics.py`. The metrics now compare each result with an expected label that the grader does not produce, and they are `null` when no such label exists.
2. **Manifest not enforced on load** in `finance_eval/runner.py`. The runner now checks the bytes against `MANIFEST.json` before any grading or model call, and it fails closed.
3. **Mock run rewrote a tracked file.** Mock output now goes to the gitignored `finance_eval/output/` directory.

Still open:

1. **Planted labels are not independent labels.** The reference labels for precision and recall were written by the author of the graders.
2. **Seeded human reviews** are counted in `judge_human_agreement`.
3. **Regression comparability** is not checked: the dataset hash, case set, and grader version are not compared.
4. **Evidence integrity** is limited to hashes that the writer can recompute.

The first two fixes started from a proposed patch, which was then refined. The refinement records `reference_label_source`, sets gold mode's labels to all should-pass, returns `null` metrics for live and custom runs, and makes the CLI exit with code 2 and a clear error instead of a traceback. Evidence logs from the fix run are `fixes-evalforge-case-study-rerun.log`, `fixes-evalforge-tamper.log`, and `fixes-evalforge-mock-output.log` in the review pack.
